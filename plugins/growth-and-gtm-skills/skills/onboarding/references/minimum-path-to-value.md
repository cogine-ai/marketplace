# Minimum Path to Value

The minimum path to value is the fewest necessary steps to a useful outcome that lets the user judge whether the product fits. Define that outcome from the product's activation evidence before editing the flow.

## Inventory → remove → reconstruct

1. **Inventory:** list each screen, input, confirmation, permission, setup dependency, and empty state between signup and the value event. Record completion and drop-off evidence where available.
2. **Remove or defer:** ask whether each step is needed for that outcome now. Remove, defer, prefill, or make optional the nonessential work. Retain steps required for correctness, necessary access, or the accepted product contract.
3. **Reconstruct:** put the remaining steps in the order that gets the user to a real usable result. Reveal advanced configuration when needed. Check the flow with the relevant cohort and iterate from observed stalls.

## Evaluate the change

Compare step completion, time to value, activation, and subsequent retention using the existing event definitions and a business-appropriate observation window. Record the old and proposed paths, why each step remains or moves, and what would validate the change. A shorter flow is a hypothesis until the outcome is verified.

Show only progress the user or system has actually completed; sample content and skipped setup are not completed customer actions. Avoid projecting another product's activation uplift onto this one.
